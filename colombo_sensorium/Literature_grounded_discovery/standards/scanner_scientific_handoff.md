# Applying the joint standard in the paper scanner

Read the full `schema_read(kind="joint_analysis")` resource in pages. Store the analysis as a JSON **object** in `profile.joint_analysis`. For an existing setting, read the pinned original profile, native IDs and all affected comparisons. Preserve conditional baseline provenance. A new setting has no retained baseline. A `no_change` research record carries its own `joint_analysis` for the exact baseline version. Record the finite search scope, sources read and any unassessed complement. Use partial synthesis or request materials while a material question remains open.

Use `draft_synthesis_plan` on the current draft to list compatible candidates and replacement and resource-projection opportunities against the assigned baseline. The domain cells, comparison syntheses and the reader-facing bracket describe the same guards, selected upper and lower bound IDs, envelopes, improvement regions and scoped gaps. Keep the main status in each native comparison. Use the registered summary badge and special-status labels verbatim. Retain any material open lead and its effect on the comparison. Determine closure and strictly larger domains from actual proofs, checking the witnesses against both the old and new domains.

For `literature.status=finite_scope_complete`, the research handoff includes `literature_scope` with all consulted `source_refs`, real `search_refs` for a bounded bibliographic search, and an empty `unresolved_leads` array. The mode is `fixed_sources` for a named set of sources or `bounded_search` for a completed search. Read the declared original sources through the job tools. Identify the exact finite scope in the analysis. Use partial literature coverage if the work is still under way.

For an open problem whose source does not determine a minimax target, preserve its task, oracle information, source and named unknowns. Record `profile.refinement_pending` with nonempty `reason`, `next_evidence` and native `source_refs`. Use `target.resolution = normalization_required`, incomplete synthesis, and concrete pending obligations. A profile without a defined comparison may have zero comparisons, zero bounds and an empty derived summary. A defined comparison with neither registered side uses `missing_both`. Local results require their own resolved contract and support. Approval of the documented open question does not certify an unknown bound.

The independent reviewer reads the frozen proposal's `prepared_ref`, including `/files/profile.json/joint_analysis`, the native comparisons, proofs and five-file bundle hash. For a proposal approval copy its actual `bundle_hash` into `review.prepared_hash`. Report all six boolean `joint_checks` from the review schema and explain the decisive checks and outstanding scope in assessments, issues or summary. A true check affirms accurate accounting within the stated scope, including a faithfully reported open question. A failed check leads to revision or deferral. A no-change review binds the frozen research subject, its baseline version and its new search and synthesis audit.

Read the projection preview/report's field directory and existing hashes. The regime index is `identity.json/regime_predicates`; `machine_tags.registry` is optional passthrough. The controller owns sidecars. Use `artifact_get.value_digest` for a selected value and existing bundle/file hashes, without reserializing full documents.
