# Scientific instruction binding

The existing new-profile researcher, existing-profile updater and independent profile reviewer remain the scientific roles. No third synthesis or approval role is added.

`load_instructions` now actually loads the complete `standards/status_taxonomy.md`, `standards/status_taxonomy.json` and `standards/joint_parameter_standard.md` for all three roles, in the same order and version. These are full startup bodies rather than an optional directory entry. The complete joint-analysis JSON schema remains available through `schema_read(joint_analysis)` and authorized resource pagination; it is not pasted into each startup prompt.

The manifest records each actual loaded body hash, the status version, joint-analysis version, full joint-schema hash, all standard/schema dependencies and the complete instruction/contract hashes. `verify_instruction_manifest` checks mandatory membership, full body inclusion and actual hashes. Missing or changed resources cannot verify under an old manifest. The existing runner also refuses recovery when the instruction manifest changes; use an explicit new revision rather than silently resuming an old scientific contract. This mechanism checks resource identity and inclusion, not the truth of any theorem.

The joint standard carries the full scientific requirements used by Atlas maintenance: joint/fixed/normalized variables and uniform constants; mathematical domain accounting and secondary slices; compatible guarded envelopes and excluded alternatives; source validity versus actual improvement; structured candidate/replacement/projection/material-lead obligations; native publication of proved closure; and strict domain-extension witnesses. A seed or nearest neighbor is a lead rather than old-baseline authority. The producer must still check sources, proofs and native cost/guarantee mappings, and the independent reviewer must assess them.

Each new or updated profile carries `joint_analysis.version=2`. For finite completion, declare the optional top-level `profile.research_scope` before freeze; it supplies finite scope, `queries_complete` and exact `unresolved_leads`. The controller binds this declaration to the actual job's search/read logs, and final `research.research_scope` must agree. An explicitly unassessed profile need not manufacture completed search work. Preserve pending leads verbatim as structured obligations and in `pending_obligations`; a partial supported proposal can be reviewed without claiming full synthesis, exhaustive literature or an open problem.

Profile review includes six `joint_review.checks`: `parameter_roles`, `guarded_envelopes`, `domain_accounting`, `improvement_regions`, `provenance` and `display_consistency`. Each is an explicit verdict/reason record. The review binds `prepared_hash` to the exact five-file bundle, `analysis_hash` to the exact analysis and `science_context_hash` to `prepared.science_hash`. This last binding covers the actual research context, baseline and contract fingerprints outside the five-file payload. Any relevant change invalidates the old approval. Hash consistency grants no proof, source-read credit or inherited scientific acceptance.

Existing-setting `no_change` requires canonical current statuses, a resolved complete v2 analysis, completed finite queries and no unresolved material lead. It retains `profile_ref=null`; the controller supplies a read-only five-file `science_prepared_ref` snapshot with the same hashes for the independent review. A legacy baseline without v2 needs a supported update or missing-materials outcome. No-change approval does not write Atlas or issue an ingestion receipt.

The setting expander and expansion reviewer receive compact scope and closure responsibilities in their own actual role protocols. They preserve the full authorized mathematical domain and do not substitute a fixed-parameter slice or infer optimality from a neighboring profile. Their specification review remains distinct from whole-Atlas identity and final scientific adoption.

The 60,000-character input limit and 12,000-character tool cap remain unchanged. Shared and role protocols consolidate repeated generic instructions while retaining scientific requirements. Tests measure the actual loaded text plus current tool/handoff schemas, representative input references and a real `schema_read(joint_analysis)` response. They also cover mandatory body inclusion, missing/tampered hashes, source-resource changes, rejected recovery before any provider call, and the unchanged role registry. Large sources still require bounded pages and the normal segment/checkpoint workflow.
