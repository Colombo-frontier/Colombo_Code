# Scientific contracts and migration

The expansion frontend and paper frontend use the same native status and joint-parameter publication contracts. The public distribution is `structural-exploration`. Install from source in a dedicated Python 3.11+ environment with the desired provider extras. Optional local archives are generated with `python -m build`; install the resulting wheel from `dist/`. Binary archives are not tracked in this source tree. Use a dedicated environment and do not co-install `oracle-atlas-agents` or Maintenance packages providing the same `oracle_atlas` namespace.

## New authoring and review obligations

`standards/status_taxonomy.json` is the versioned closed status contract. Each top-level comparison has one of the ten native codes. Its summary counts, missing-side union, gap classes, special states and badges must agree with those actual comparisons. Unknown codes are rejected rather than translated. Exact zero/one costs and saturation are attributes of a guarded comparison. `gap_causes` records one or more of the six declared reasons; it supplies no proof or literature-completeness credit.

Every newly written profile has version-2 `joint_analysis`: an explicit resolved target, parameter and hidden-constant conventions, domain accounting, candidate-bound participation, guarded envelopes, native provenance, synthesis obligations and literature coverage. A legitimate fixed finite family can have no varying continuous parameters. Draft generation remains explicitly unassessed; it does not manufacture proofs or a resolved target.

Research supplies `research_scope` with an explicit scope, `queries_complete` and `unresolved_leads`. A profile may declare the identical scope before freezing when its finite-literature claim needs that context; the final research handoff must agree. New settings have no accepted baseline. Updates bind the exact frozen baseline; neither an ID match nor a prior approval recertifies changed science.

Independent profile review supplies six named assessments with verdicts and reasons, and binds the prepared five-file hash, exact analysis hash and frozen science-context hash. This is separate from individual bound approval and human approval of the exact expansion proposal. Status and joint checks run while drafting and again at the native writer; only a commit receipt establishes ingestion.

## Historical profiles and interrupted work

Historical native profiles remain readable and searchable. A new write that lacks the current status/analysis contract is intentionally rejected. Resolve missing material explicitly in a new draft with independent review; do not bulk-rewrite old profiles or assign synthetic proofs to real historical mathematics.

Updated instructions, schemas and science context invalidate stale preparation/review state. Start a fresh versioned run when the contract changed and retain old receipts and failed attempts. Adding a bound changes the joint synthesis environment, so an unchanged old bound may still require a fresh applicability review. Standalone proposition reuse remains a separate, explicitly scoped mechanism.

## Verification scope

The included offline examples use scripted finite toy judgments and actual tools, independent jobs, publication gates and local five-file transactions. They explicitly allow 16 context segments and 90 turns per job to traverse the larger contracts; the 60000-character input cap and finite call/job limits remain in force. Those fixture settings do not raise production defaults.

Software tests, resource/package checks, synthetic receipts and read-only compatibility checks do not establish real-model research quality, mathematical correctness or exhaustive literature. Software migration does not itself add any conclusion to the user's production Atlas. Record live model, source-network and actual publication acceptance separately.
