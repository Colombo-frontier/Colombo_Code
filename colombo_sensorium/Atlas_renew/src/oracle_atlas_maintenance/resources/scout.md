Investigate the supplied existing setting and propose a supported bracket/synthesis change with a complete account of the affected joint-parameter envelopes. Use the compact baseline and candidate catalogue for targeted research, reuse unchanged evidence conditionally, and read decisive premises before adoption. You are not discovering or matching settings.

Avoid repeating already screened equal/dominated evidence when its underlying support remains unchanged. This summary is abbreviated, unapproved working memory from the same baseline/policy/Atlas semantics; it is not inherited scientific approval or proof of a completed search. Reread decisive archived sources through `source_read`, verify current applicability and cutoff, and complete a fresh valid query chain for the current scope. Do not reconstruct or adopt a previous patch from a finding summary, and do not infer that clipped or omitted previous work was resolved.

1. Use `baseline_catalog`, `synthesis_catalog` and compact comparisons to locate relevant rows. Read the fixed contract, target view/guarantee, quantity/resource and guards. Resolve the joint variables, normalizations, fixed parameters and allowed hidden constants from the frozen baseline and the complete supplied schema. `joint_analysis_input` states whether an existing analysis is available; first annotation does not supply a generic skeleton to read. Report conflicts with native metadata explicitly. Account for every existing comparison before complete no-change; a partial candidate must finish its affected cone. A compact preview is not the full profile.
2. Build a small finite research map before choosing the update: promising main-rate upper/lower routes, important unrepresented regions, compatible bounds missing from envelopes and valid nearby transfers. Also check zero/one-query consequences, low-dimensional branches, saturation and guarantee containment. An already cited source can support a newly recognized change. A cheap nontriviality proof does not replace the map or terminate the planned check of a plausible stronger route. Search targeted primary theorem/version text within the window/cutoff; avoid a full unrelated survey. Default maintenance must execute at least one discovery query using task/oracle/complexity keywords, not only a known paper ID or exact known title. Prioritize it before a second identity lookup of the same paper and before polishing a large first annotation, within the existing configured search cap. Record the actual route and limits in scope.note; a finite query is not exhaustive literature coverage.
3. Filter cheaply. An equal/dominated result normally has `impact: no_effect`; a result requiring changed contract/guarantee/resource has `impact: incomparable` and a precise reason. Keep relevant unresolved candidates in `scope.unresolved_leads`.
4. For a potential change, verify the full source-to-target mapping: model/geometry, native query capabilities, algorithms/adaptivity, output, metric, probability/expectation, query accounting, parameter dependence, and exact region. Supply any necessary short proof or transfer explicitly in native evidence/proof records.
5. Recompute the affected guarded envelopes from compatible old and new bounds, accounting for each mechanical candidate. Separate source validity, adopted intersection, actual improvement and non-improvement regions. Check saturation, strict endpoints and newly closed subregions; keep asymptotic crossovers distinct from exact thresholds. Record the residual domain explicitly. A correction may require deactivating a bound and removing every affected active reference. Short derivations may cite exact accepted premises and state the complete new step without duplicating unrelated proofs. Freeze a coherent local update while leaving unrelated broader work pending.
6. Return the exact scout schema object. Do not write a profile directly.
