# Operations and evidence boundaries

## Budgets and concurrency

The example role base is 64 tool calls with an additional control reserve of 10. Adaptive allocation can provide up to 128 calls for a role, subject to the configured cap and remaining setting allowance. It estimates complete mandatory reads, includes a bounded margin, and reserves status, checkpoint and handoff capacity. An estimate is not observed reading credit or a guarantee that an uncertain study will finish.

A single baseline/cutoff/semantics cycle shares 1800 active seconds, 256 tool calls and four sessions across research, review, retries and continuation. Controller work is also accounted for. Another plan cannot silently replenish the same cycle. An active reservation holds capacity; reserved time is not evidence that all of it has already elapsed.

The parallel example permits up to 20 independent settings. Each worker owns its runner, role host and database connection. Research precedes review within one setting. Per-setting sums, overlapping process time and batch wall time are different measurements and must not be added or compared as though interchangeable.

The initial-input ceiling includes complete instructions and the exact inline context with frozen-artifact hashes. Only permitted preview representations can move behind hash-bound references. Mandatory scientific fields remain. In the controller-bound finite reviewer lane, a whole derived catalog may move to an exact artifact only after ordinary leaf projection is insufficient. Complete actual catalog reads and their estimated calls are added. If mandatory input still cannot fit, execution refuses before starting a model; raising a cap is not an automatic fallback.

## Deadlines and checkpoints

A role's process deadline covers its complete native session, not just network requests, and does not restart after a successful tool call. Literature requests have a separate timeout. Cooperative closing reserves time for an honest final handoff and stops opening new network research. It is observed on subsequent tool calls; it cannot guarantee that an opaque backend operation returns promptly. A hard deadline still terminates an overdue process and rejects late tool writes.

`maintenance_status` reports remaining capacity. `checkpoint_save` records bounded unapproved progress and pending work; `checkpoint_read` reads the current stage's checkpoint. `handoff_validate` parses and checks the proposed report, nested JSON, current scope, exact evidence references and available structural contracts. It supports repair after a failed mechanical preflight. It neither proves the mathematics nor replaces the authoritative controller or independent reviewer.

Compact handoff archives the complete mechanically valid report under its exact hash and allows a small final reference. The native turn must still finish, and current request, role, artifact, journal and complete report checks still apply. A checkpoint, partial output or another stage's artifact cannot substitute for a completed formal handoff.

## Publication safeguards

Before adoption the controller repeats current proposal, taxonomy, joint-analysis, evidence and retention checks. The prepared fingerprint binds all five native files. The independent reviewer must confirm parameter roles, guarded envelopes, domain accounting, improvement regions, provenance and display consistency, with its own complete required reads and the exact prepared analysis hash.

Zero-cost endpoints, exact finite costs and saturation belong to precisely proved regions. They do not create new primary native status codes or make an entire profile fully optimal. Derived summaries must agree with actual canonical comparison statuses and counts.

A closed partial original scout can be used only as an explicit unapproved witness for new independent review. Its failed IDs, journal, finite audit and unresolved obligations remain pinned. This does not make the scout clean or the search complete. A new clean reviewer and every source/baseline/prepared gate remain necessary; only partial adoption is possible and no successful complete-maintenance watermark is written. All other reuse retains its strict eligibility requirements.

Do not edit approved bundles, overwrite old evidence, reuse a prior verdict for a changed policy, or publish a manually patched profile. Keep a complete backup before applying to an important Atlas. Native commits are authoritative transactions; a profile file alone is not a complete backup or rollback.

## Observe without exposing private data

Public telemetry records lifecycle events, tool names and timing spans. Nested phases overlap; do not sum them as independent work. Time outside local tool execution is opaque: it cannot by itself identify model computation, service queueing or provider delay.

Usage counters describe only what the backend exposes. Cached input is a subset of input, not an additional token total. Internal native calls, invoice cost and other platform activity can remain unknown. Imported scout metrics must not be counted again as new research sessions.

Keep raw backend events, prompts, reasoning, source archives, credentials and complete operational contexts private. They are not distributable component assets. Runtime journals and snapshots contain evidence identities, dates and integrity bindings needed for local replay; publish only deliberately reviewed summaries, never an entire work directory.

Use `checkpoint` for inspection and `continue` only for an explicit paid-capable continuation. A known unstarted backend launch can be assessed through `reconcile-startup`, which requires exact evidence bindings and records an append-only correction. Uncertain execution cannot be erased or relabelled as free, and an adopted or approved candidate cannot be refunded this way.
