# Upper-bound review supplement

Use this supplement for the supplied Upper-bound evidence within the current audit/review scope. It applies to proof review and independent report confirmation; it is not a separate review stage. The runner freezes this file with the Cell's instruction pack. Reviewers receive it as `input/upper_bound_review_guidance.md`; local auditors receive the installed `upper_bound_review_guidance.md`.

## Check the actual claimed relationship

Read the assigned responsibility, exact Algorithm and claimed Guarantee. For a fixed-Algorithm Task, a result for another Algorithm does not complete it. For a design Task, follow the actual final variant through every dependency; an earlier variant's successful analysis is not enough. Claims, constructions, Arguments and sources must be identifiable in the authorized fixed input.

Check the relevant Function Class, Oracle model, allowed information, initialization, Output/Metric, expectation or probability convention, parameter regime and quantifiers. In particular, the constructed Algorithm must work for the declared instances with the allowed public information; hidden instance quantities cannot silently supply tuning or stopping decisions. Verify an asserted uniform Guarantee rather than observations on selected examples.

Inspect the derivation required by this particular proof. A valid recurrence may still require summation, averaging, best-iterate selection, a stopping/output argument or other conversion to the claimed Metric. Do not impose a fixed sequence of five obligations or a preferred proof technique; report a gap only when it affects a claimed conclusion.

## Check Resource accounting and composition

Identify what the bound counts. Convert iterations to the full counted Resource with all relevant Oracle calls, approximate inner solves, batch sizes, initialization, restarts, repeated trials or success amplification. Expected and high-probability cost or error are distinct. Check constants, parameter dependence, normalization and valid regime to the extent needed for the stated result. An optional `complexity_profile` is a readable summary, not independent evidence.

A component Claim being proved does not establish the parent Guarantee. Inspect the composition Argument and current scoped evidence. A required positive Lemma that was refuted blocks its route. Obligation `work_status`, nonempty evidence lists, child completion and imported child audit labels cannot replace a correctly bound closing Argument and the normal review of the full claimed result.

## Keep review evidence bounded

Library entries can provide Algorithm descriptions or external Theorems; their provenance/status is not current-task certification. Check the relevant exact statement, assumptions and application, using the authorized fixed evidence and the common source rules. Do not require re-proving every cited external Theorem, and do not assume a live ref supplies missing content. Preserve missing or truncated source coverage as a limitation.

Numerical evidence and failed proof attempts can motivate candidates or identify obstructions; they do not prove a full-class Upper Bound or impossibility. Report the smallest precise unsupported step and its effect on the assigned conclusion. During report confirmation, verify the review's alleged error or gap against the same fixed Algorithm, Claim and proof instead of repeating its labels. Keep the existing verdict, confirmation, conflict and handoff semantics.
